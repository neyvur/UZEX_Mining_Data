# UZEX Data Agent — ИИ-агент по биржевым сделкам (RU / UZ)

Telegram-бот (+ веб-страница как запасной канал), который отвечает на вопросы о 500 000 сделок UZEX (2022 — окт. 2026) **только по данным**.
Если ответа в данных нет — прямо говорит «В данных ответа нет».

## Как это работает
1. **Данные** (`build_db.py`): 5 годовых реестров приведены к единой схеме (разные форматы дат/сумм: `"314 565 712"`, `dd.mm.yyyy`, datetime → ISO и числа),
   присоединены карточки контрактов, участники, брокеры и курс USD. Результат — SQLite `uzex.db` (500 000 строк, совпало с заявленным числом).
   Добавлены: `amount_uzs / amount_usd` (экспорт в USD пересчитан по курсу дня), `volume = количество × лот`, укрупнённый товар `product_family` (по коду ТН ВЭД), `product_key` (нормализованное название).
2. **Агент** (`agent.py`): LLM (Gemini, запасной Groq) не «знает» ответ, а пишет **SQL** → выполняется на реальных данных (read-only, только SELECT, таймаут) → результат возвращается LLM → финальный ответ строится из результата.
   Инструменты: `sql`, `search_products` (нечёткий поиск названий товара), `search_entities` (компании/брокеры → ИНН/код).
3. **Защита от выдумок**: (а) ответ без выполненного SQL отклоняется; (б) пустой результат → агент обязан перепроверить написание, затем сказать «нет данных»;
   (в) программная проверка: каждое число (≥5 цифр) в ответе должно присутствовать в результатах SQL — иначе ответ возвращается на исправление, а при повторе заменяется на «нет данных».
4. **Прозрачность**: под ответом — раскрывающийся блок «Основа ответа» с SQL-запросом.
5. **Языки**: RU и UZ (лат./кир.) — LLM переводит вопрос в запрос, отвечает на языке вопроса. Лимит 75 сек на вопрос (требование комиссии — 90).
6. **Надёжность**: цепочка моделей Gemini 2.5-flash → 2.0-flash → Groq llama-3.3-70b → gpt-oss-120b; при 429/недоступности — автопереключение.

## Запуск
```bash
pip install -r requirements.txt
cp .env.example .env     # вписать TELEGRAM_TOKEN, GEMINI_API_KEY, GROQ_API_KEY
# база: либо положить готовый uzex.db.gz рядом (распакуется сам), либо собрать из xlsx:
python build_db.py ./папка_с_xlsx uzex.db
python bot.py
```
Команда `/diag` в боте проверяет доступность LLM и базы. `python eval.py` — самопроверка на вопросах RU/UZ с эталонным SQL (в т.ч. вопросы, на которые ответа в данных нет).
Если задан `PORT` — поднимается веб-страница с тем же агентом и `/health`.
